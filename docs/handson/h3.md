# H3 電源基板のレイアウトと発注

**時間の目安：3 時間**　｜　対応：[3-7](../part3-power/3-7-power-board.md)、[第9部](../part9-build/index.md)

## ステップ

- [ ] 基板の大きさと取りつけ穴を、ロボットの機構に合わせて決める
- [ ] ネットクラス（Power：1.0 mm 以上）を設定する
- [ ] コネクタ・スイッチ端子を基板の端に置く（XT30 の差しこみ口が外を向く）
- [ ] 電池の幹線を 2 mm 以上で、短く引く
- [ ] レギュレータのコンデンサを、データシートのとおり近くに置く
- [ ] 裏を GND のベタに、表面実装の GND の横にビア
- [ ] テストポイントを、ロボットに組んでも手が届く場所に
- [ ] DRC のエラー・未接続を 0 に
- [ ] 3D ビューアでコネクタの向きを確かめる
- [ ] シルクに基板の名前・バージョン・日付
- [ ] [9-1](../part9-build/9-1-order.md) の「注文の前に」のチェックをすべて済ませる
- [ ] GitHub に push し、Actions の DRC が通ることを確かめる（チーム用リポジトリでも同じワークフローを使える）
- [ ] JLCPCB に注文する（先生・大人と一緒に）

## 合格条件

| 項目 | 目安 |
|---|---|
| DRC のエラー・未接続 | 0 |
| 電池の幹線 | 2 mm 以上（または ベタ） |
| GitHub Actions | 緑（成功） |

## 困ったとき

- **幹線が太くて通らない**：表と裏の両方に引いてビアを何個も打つ、またはベタ（ゾーン）で作る。
- **Actions が赤い**：Artifacts の `*-drc.json` を開いて、何のエラーか確かめる。手元の KiCad 10 でも同じ DRC を走らせる。

## 発展課題

1. 電流が一番多いところの温度上昇を、[計算ツール](../tools/index.md#trace)で見積もる。
2. 部品の実装（PCBA）の見積もりをとり、手はんだと比べる。
