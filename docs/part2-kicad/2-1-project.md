# 2-1 プロジェクトの作り方

## ねらい

- KiCad のプロジェクトを作り、中のファイルの役割を説明できる
- KiCad のプロジェクトを Git で管理できる

## プロジェクトの中身

KiCad のプロジェクトは、1 つのフォルダに次のファイルがまとまったものです。

| ファイル | 中身 | Git に入れる |
|---|---|---|
| `名前.kicad_pro` | プロジェクトの設定（ネットクラス、デザインルールなど） | 入れる |
| `名前.kicad_sch` | 回路図 | 入れる |
| `名前.kicad_pcb` | 基板 | 入れる |
| `名前.kicad_prl` | 画面の状態（どのレイヤーを見ていたか） | 入れない |
| `名前-backups/` | 自動バックアップ | 入れない |
| `fp-info-cache` | フットプリントの一覧のキャッシュ | 入れない |
| `*.lck` | 開いている間のロックファイル | 入れない |

教材のリポジトリの `.gitignore` には、入れないファイルがすでに書いてあります。

## 手を動かす：プロジェクトを作る

1. KiCad を起動し、「ファイル → 新規プロジェクト」を選びます。
2. 保存場所を選び、名前を `my-led` にします。「新しいフォルダを作る」にチェックが入っていることを確かめます。
3. 左のツリーに `my-led.kicad_sch` と `my-led.kicad_pcb` ができます。

## ライブラリ

部品の情報は 2 つに分かれています。

- **シンボル**：回路図に描く記号（抵抗のギザギザ、IC の四角）。ピンの番号と名前を持つ。
- **フットプリント**：基板の上の形（パッドの位置と大きさ）。

KiCad には標準のライブラリが入っていて、`Device:R`（抵抗のシンボル）、`Resistor_SMD:R_0805_2012Metric`（0805 の抵抗のフットプリント）のように「ライブラリ名:部品名」で呼びます。

!!! tip "標準ライブラリにない部品"
    標準にない部品は、自分で作るか（[2-3](2-3-footprint.md)）、メーカーや部品店が公開しているデータを使います。作った部品はプロジェクト用のライブラリ（`kicad/lib/` など）に入れて、チームで共有します。

## Git で管理する

KiCad のファイルはテキストなので、Git で差分を見られます。

```bash
cd my-led
git init
git add my-led.kicad_pro my-led.kicad_sch my-led.kicad_pcb
git commit -m "LED 基板を作り始めた"
```

- **保存したらコミット**する習慣をつけると、「昨日の状態に戻したい」ができます。
- 2 人で同じ `.kicad_pcb` を同時に編集すると、マージがむずかしいです。基板は「今は誰が触るか」を決めて作業します。

!!! warning "自分のチームの基板は公開リポジトリに入れない"
    このサイトの公開リポジトリには、教材用の架空の基板だけが入っています。自分のチームの実際の回路図・基板は、**非公開のチーム用リポジトリ**に置きます（[付録](../appendix/team-repo.md)）。公開リポジトリには「うっかり公開チェック」が入っていて、`kicad/projects.txt` に書いていない KiCad ファイルはコミットできないようになっています。

## チェック問題

1. `.kicad_prl` を Git に入れないのはなぜですか。
2. シンボルとフットプリントのちがいは何ですか。

??? success "答え"
    1. 画面の表示状態など個人の設定で、人によって変わるから。入れると、意味のない差分が増えます。
    2. シンボルは回路図の記号、フットプリントは基板上のパッドの形。
